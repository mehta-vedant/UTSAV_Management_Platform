Current high-level design

One app, clear boundaries, controlled integrations.

UTSAV is a modular monolith: one Next.js application containing UI and trusted server code. PostgreSQL stores connected records; SES sends email; S3 stores private evidence; Gemini is an advisory integration.

Protected financial request

  1. Browser opens /[orgSlug]/dashboard/expenses.
  2. Server resolves slug, reads session, checks OrganizationMember and role permission.
  3. A service validates the request and scopes the query to that organization.
  4. Prisma reads/writes PostgreSQL, then the UI refreshes trusted data.
  5. For a receipt, S3 receives file bytes directly via a temporary upload permission; PostgreSQL receives only metadata.

AI cannot query the database, approve expenses, or mutate records. This prevents a chat prompt from becoming an authorization bypass.

Tenant boundary now

Organization-owned records include organizationId. Event assignments and registrations now include it too, and event/member checks prevent cross-organization linking. That makes the tenant helper valid for these child records rather than pretending the parent relationship is enough.

Future only

Idempotency keys for every money write, SES feedback, monitoring, backups, queues, caching, and a double-entry ledger remain sensible next steps. Microservices do not yet solve a measured problem.
