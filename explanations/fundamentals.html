How a website works before we discuss UTSAV.

Read this first. A technical word is just a name for a simple job. We will define the job, use an everyday analogy, then show where UTSAV uses it.

1. Browser to server2. URLs and routes3. Frontend4. Backend and APIs5. Database6. Glossary

1. What happens when you open a website?

Browser means Chrome, Edge, or Safari: the app that displays websites. A server is a computer that receives requests and sends answers. A request is you asking for something; a response is the answer. Think of a restaurant: you are the browser, the waiter carries the request, the kitchen is the server, and the meal is the response.

You open a URL
→
Browser sends request
→
UTSAV server decides
→
Database supplies data
→
Browser displays page

In UTSAV, the browser asks for a page, Next.js runs server code, PostgreSQL stores/retrieves records, then the browser receives HTML and interactive JavaScript.

2. What is a URL and route?

A URL is a web address, such as utsavmanagement.me/login. A route is the rule that says which code handles that address. A static route is fixed, like /login. A dynamic route contains a changing value: /[orgSlug].

What is a slug? A slug is a readable, URL-safe name such as ganesh-utsav. A database ID is an internal unique label such as clx.... UTSAV uses the slug in the URL so humans can read and share it, then resolves it to the internal organization ID for database work.

3. What is frontend?

The frontend is what a person sees and touches. HTML gives the page structure, CSS gives it appearance, and JavaScript makes it react to clicks. React lets developers build the screen from reusable pieces called components: a button, modal, sidebar, or donation form.

Next.js is the framework UTSAV uses to organize pages and decide whether code runs on the server or in the browser. A server component can safely load data before sending a page. A client component is used when the browser needs live interaction, such as opening an expense modal.

4. What is backend, API, and server action?

The backend is code that users do not directly see. It validates a request, checks permission, applies business rules, and reads/writes data. An API (Application Programming Interface) is a defined way for one program to ask another program to do work. An endpoint is a specific API address.

UTSAV mostly uses server actions: secure backend functions called by the UTSAV UI itself. This avoids creating a public API for every dashboard button. The NextAuth route is an API route because the authentication library expects HTTP endpoints.

5. What is a database?

A database is organized long-term memory. PostgreSQL stores data in tables. A table is like a spreadsheet: a row is one item, a column is one kind of information. An Organization row might have name, slug, and start date. A relation connects tables: an expense belongs to one organization.

Prisma is an ORM—Object Relational Mapper. It lets TypeScript code ask for records without manually writing every SQL query. SQL is the language databases understand; Prisma translates structured calls into SQL.
