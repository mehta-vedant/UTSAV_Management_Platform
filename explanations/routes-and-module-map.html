Finding your way around source code

A URL is an address. A route is code waiting at that address.

The map is simple: a page displays a screen, an action accepts a change, a service owns the rule, and Prisma talks to PostgreSQL.

Folders become routes

Next.js App Router uses a convention: a folder inside src/app represents part of a URL and its page.tsx renders the screen. src/app/login/page.tsx therefore becomes /login.

Static and dynamic routes

A static route is fixed, such as /login. A dynamic route has a placeholder in square brackets. src/app/[orgSlug]/dashboard/page.tsx can serve many organizations: /ganesh-utsav/dashboard and /navratri-2026/dashboard.

Slug: a readable, URL-safe label, such as ganesh-utsav. It is different from an internal database ID. It selects an organization but does not grant access; server code still verifies membership and permission.

What happens after a private route opens?

  1. Browser requests /ganesh-utsav/dashboard/expenses.
  2. Page receives orgSlug = ganesh-utsav and server code identifies signed-in user.
  3. Membership/permission and organization are resolved; a typed URL is never proof of access.
  4. Service/Prisma loads tenant-scoped data from PostgreSQL.
  5. React renders HTML. Interactive components hydrate in the browser.
