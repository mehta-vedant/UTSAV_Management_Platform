One building, many locked apartments

Multi-tenancy means every organization stays separate.

An organization is one tenant. A user can belong to several organizations, with a different role in each. A URL chooses an apartment; it does not hand over a key.

Event-child protection

Implemented now EventAssignment and EventRegistration now store organizationId. A migration backfills it from the parent Event. Service code verifies that an event and assigned member belong to the same tenant. This makes direct child queries safe to tenant-scope.

Receipt privacy flow

  1. Server checks the requester owns the expense, or has a finance-management permission.
  2. Server creates a random object key in the correct organization S3 prefix.
  3. Browser gets a five-minute upload form, never AWS credentials.
  4. Server confirms the uploaded object before marking the database record uploaded.
  5. Uploader, Treasurer, or Admin can request a two-minute view link. No public route gets one.
Do not confuse hiding UI with security

Removing an “Approve” button does not stop a forged request. Every important server action repeats session, membership, permission, and tenant checks.

Honest next security improvements

Add idempotency keys to sensitive writes, structured error monitoring, backup/restore drills, SES bounce/complaint handling, and malware scanning for uploaded files. These are improvements, not claims about the current code.
