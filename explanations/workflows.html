User + session
  1. /signup collects name, email, optional phone and password.
  2. requestSignupOtpAction validates input and stores a temporary record with password/OTP hashes.
  3. SES sends the code. No User row exists yet.
  4. verifySignupOtpAction checks expiry, attempt limit and exact OTP hash, then atomically creates the User.
  5. An HttpOnly enrollment cookie stops another browser changing pending details. Resend rotates only OTP state.

Existing-account OTP login

On /login, requestOtpAction creates hashed EmailOtp state and SES sends the code. NextAuth consumes a correct code and creates a session for an existing account. Unknown emails are sent to signup; login OTP does not create blank users.

Organization and membership

/dashboard/create creates an Organization and creator OrganizationMember. Authorized members use /[orgSlug]/dashboard/members to create OrganizationInvitation; the accept page validates recipient, token and expiry before membership is created/restored.

Finance

Donation UI calls donation.actions.ts and the finance donation service. Expense UI calls createExpenseAction; the service requires finance:create, creates a PENDING Expense and audit information. Approve/reject requires finance:approve; a guarded update changes only a still-pending expense.

Operations and public pages

Events, volunteers and Bhog use their own actions/services. Festival-only public pages use purpose-built public queries; reports, exports and audit trail remain private organization features protected by membership and role permission.

Known limitation

Event assignments and registrations need parent-event tenant scoping or an explicit constrained organization key before being described as complete workflows.

Interview line

“A UTSAV workflow is a controlled state change: action validates, service checks membership/permission and business state, Prisma writes organization-scoped data, then trusted UI refreshes.”
