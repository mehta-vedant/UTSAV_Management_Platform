1. What Is This Project? In Plain English

UTSAV is a web app for managing festivals, clubs, or cultural organizations. It helps organizers track donations, expenses, events, members, volunteers, bhog or prasad offerings, invitations, and public transparency pages in one place.

The users are admins, treasurers, committee members, and volunteers. The problem it solves is simple: instead of managing money and festival work through WhatsApp groups, notebooks, and scattered spreadsheets, the organization gets one structured system with roles, records, and history.

Evidence: README.md says UTSAV is a multi-tenant governance platform that digitizes operations for cultural organizations and festivals. 
UTSAV is a production-grade, multi-tenant governance platform designed to digitize
the operations of large-scale cultural organizations and festivals.

2. What's a Tech Stack and What's Ours?

A tech stack is the set of programming languages, frameworks, libraries, databases, and tools used to build an app.

Next.js

A web framework, meaning a tool that organizes both pages users see and server-side code that handles data.

React

A frontend library, meaning a tool for building buttons, forms, tables, and screens in the browser.

TypeScript

JavaScript with type checking, meaning it helps catch mistakes before the app runs.

Prisma

An ORM; an ORM is a tool that lets code talk to a database using objects instead of writing raw SQL every time.

PostgreSQL

A database, meaning the place where long-term app data like users, donations, and expenses is stored.

NextAuth

An authentication library; authentication means checking who the user is when they log in.

bcryptjs

A password hashing library; hashing means turning a password into a scrambled value so the real password is not stored.

Tailwind CSS

A styling tool that gives short class names for colors, spacing, layout, and typography.

Radix UI

A UI primitive library; UI primitives are accessible building blocks like dialogs and dropdowns.

lucide-react

An icon library that provides reusable visual icons.

Framer Motion

An animation library that makes UI movement and transitions easier.

Zod

A validation library; validation means checking that incoming data has the correct shape before using it.

Vitest

A testing framework that runs automated checks to prove code behaves correctly.

Resend

An email service library that can send invitation or notification emails.

User Interface

React, Tailwind, Radix, lucide, Framer Motion build what the user sees and clicks.

App Framework

Next.js routes pages, layouts, server actions, and authentication routes.

Business Logic

Services in src/modules enforce rules for money, members, events, and access.

Data Layer

Prisma talks to PostgreSQL where the permanent records live.

3. Manifest Files, Line-By-Line-ish

A manifest file is a project instruction sheet that says what the app is called, how to run it, and which outside packages it needs.

The main manifest is package.json.

4. How Does the App Actually Start Running?

An entry point is the first important code path that runs when the app starts or when a user visits a page.

Run command: npm run dev runs next dev from package.json.
Next.js scans routes: the src/app folder becomes the app's route map.

Step 7: Tenant-Scoped Prisma Protects Data

A tenant is one customer or organization inside a shared app. Multi-tenant means many organizations share the same app and database, but their data must stay separated.

File: src/lib/access-control.ts

export const getTenantPrisma = (organizationId: string) => {
  return prisma.$extends({
    query: {
      $allModels: {
        async $allOperations({ model, operation, args, query }) {
          const tenantModels = [
            "Donation",
            "Expense",
            "OrganizationMember",
            "BhogItem",
            "Volunteer",
            "Event",
            "VolunteerTask",
            "AuditLog",
          ];
        }
      }
    }
  });
};

8. Why Were These Choices Made?

Next.js Instead of Separate Frontend and Backend

Alternative: build one React app and one Express or FastAPI backend. This project likely chose Next.js because one codebase can contain pages, server actions, authentication routes, and server-rendered data.

PostgreSQL Instead of Files or Browser Storage

Alternative: store data in JSON files or only inside the browser. PostgreSQL makes sense because money records, members, roles, and audit logs need reliable shared storage.

Prisma Instead of Raw SQL Everywhere

Alternative: write SQL manually for every query. Prisma makes database access more readable and connects well with TypeScript, which lowers the chance of field-name mistakes.

Role-Based Access Control

RBAC, or role-based access control, means permissions are based on roles like admin, treasurer, or volunteer. This matters because a volunteer should not approve expenses, while a treasurer should access finance features.

Logical Multi-Tenancy

Alternative: create one database per organization. This project uses one shared database with organizationId on records, which is simpler and cheaper while still keeping records separated through tenant-scoped Prisma.

9. Interview-Ready Answers

Elevator Pitch

UTSAV is a Next.js and PostgreSQL platform for managing festival or organization operations like donations, expenses, members, events, volunteers, and public transparency. It uses role-based permissions so admins, treasurers, committee members, and volunteers only access what they should. The most important engineering idea is tenant isolation, where every organization's data is scoped by organizationId to avoid cross-organization leaks.

1. What does this project do and who is it for?

It helps cultural organizations and festival committees manage operations digitally. It is for admins, treasurers, committee members, and volunteers who need one reliable place for money records, events, members, and public transparency.

2. What's the architecture or tech stack, and why?

It is a modular monolith, meaning one app contains multiple organized feature areas instead of many separate services. It uses Next.js, React, TypeScript, Prisma, PostgreSQL, NextAuth, Tailwind, and Zod because those tools let the project combine UI, secure server-side logic, database access, login, styling, and validation in one maintainable codebase.

3. Walk me through what happens when a user records a donation.

The donations page checks the organization and user membership, then shows a record button only to allowed roles. The modal collects donor name, amount, category, date, and notes, sends them to a server action, validates them with Zod, checks finance permission, writes the donation through tenant-scoped Prisma, records an audit log, and refreshes the page data.

4. What was the hardest or most interesting technical decision here?

The most interesting decision is tenant isolation. Since many organizations share the same app and database, the code uses getTenantPrisma(organizationId) to automatically attach organizationId to important database operations, reducing the chance of one organization seeing another organization's records.

5. What would you improve if you had more time?

I would add stronger automated tests around access control and tenant isolation, because those are the riskiest parts of the system. I would also improve the email invitation flow, review all financial operations for transaction safety, and clean up inconsistent comments or encoding issues in documentation.
