2. What's Wrong & What's Right

What's Done Well (Keep These)

1. Tenant-Scoped Prisma Extension getTenantPrisma() auto-injects organizationId into all queries. Prevents cross-tenant data leakage at the ORM level. Defense-in-depth.
2. Comprehensive Audit Logging Before/after snapshots on every financial mutation. Full change history with AuditService.record().
3. Zod Validation at Action Boundary Every Server Action validates input with Zod before passing to services. Prevents invalid data from reaching business logic.
4. Error Hierarchy AppError → AuthenticationError → AuthorizationError → etc. Structured error flow through actionFailure().
5. Parallel Data Fetching Server components use Promise.all() for concurrent DB queries. No waterfall delays.
6. Public Transparency Architecture Separate Public*Service classes from authenticated services. Clean data access control for public pages.
7. Prasad Window System Well-thought-out domain model for time-window-based bhog offering availability with proper date/timezone handling.

What Needs Fixing

1. Static-Only Service Classes — No Real OOP Every service (OrganizationService, DonationService, etc.) uses only static methods. Classes are never instantiated. They're namespaces with extra syntax. In TypeScript, plain exported functions are cleaner.
2. Inconsistent Return Types Across Actions Some actions use actionSuccess()/actionFailure(), others return raw {success, error} objects. Client consumers need different error-handling logic per action.
3. Duplicate Authorization Patterns validateAccess() checks roles directly, requirePermission() uses the permission matrix. Both used interchangeably across services. Some actions manually query organizationMember to check ADMIN role instead of using the centralized system.
4. Task Logic Misplaced in Member Service MemberService handles both member queries AND volunteer task CRUD. Task management should live in modules/tasks/ (currently empty).
5. Redundant Organization Lookups Dashboard layout resolves org via getOrganizationBySlug(), then child page does prisma.organization.findUnique() again. Same data fetched twice per page load.
6. Organization Type Branching in Components Dashboard page has extensive isFestival conditionals with entirely different UI trees. Creates large, hard-to-read components.
7. Missing Loading/Error Boundaries No <Suspense> boundaries or error.tsx files. A slow DB query blocks the entire dashboard render.
8. as any Cast Proliferation Multiple organization as any casts suggest interface mismatches between service return types and component prop types.
9. Dead Code in FinancialService FESTIVAL and CLUB branches compute identical formulas, making the conditional pointless.
10. No next.config.js No image optimization, no custom webpack config, no redirect rules, no environment variable validation.

3. Redesign Principles

Principle 1: TypeScript-First Type Safety No as any. Every service return type explicitly defined. Every component prop typed. Every action input/output typed. Compile-time guarantees.
Principle 2: Single Authorization System One function, one source of truth: requirePermission(orgId, "permission"). No role-checking, no manual admin queries, no bypassing.
Principle 3: Functions Over Classes Services as plain module exports. No static methods, no class instantiation. Tree-shakeable, testable, simple.
Principle 4: Uniform Action Contract Every Server Action returns ActionResult<T>. Client components have one error-handling pattern.
Principle 5: Domain-Driven Module Boundaries Each module owns its models, services, types, and tests. No cross-module logic leaks.
Principle 6: Loading States & Error Boundaries by Default Every route segment has loading.tsx and error.tsx. No blocked renders.
Principle 7: Shared Data Layer via React Cache One getOrganization(slug) call per request, memoized with cache(). Passed via context, never re-fetched.

6. Multi-Tenancy — Simplified & Type-Safe

Current Approach

// src/lib/access-control.ts (current) export function getTenantPrisma(organizationId: string) { return prisma.$extends({ name: "TenantScope", query: { donation: { findMany({ args, query }) { args.where = { ...args.where, organizationId }; return query(args); }, // ... same pattern for findFirst, findUnique, update, delete, create }, // ... repeated for EVERY model } }); } // Problem: 200+ lines of boilerplate per model // Each model needs: findMany, findFirst, findUnique, create, createMany, update, updateMany, delete, deleteMany

Proposed Approach — Generic Tenant Scope

// src/server/tenant-prisma.ts import { Prisma } from "@prisma/client"; const TENANT_MODELS = [ "donation", "expense", "organizationMember", "bhogItem", "event", "volunteerTask", "auditLog", "eventAssignment", "eventRegistration", ] as const; type TenantModel = typeof TENANT_MODELS[number]; function createTenantExtension(organizationId: string): Prisma.Middleware[] { return TENANT_MODELS.map(model => ({ name: `TenantScope:${model}`, query: { [model]: { // Generic query interceptor findMany({ args, query }: { args: any; query: Function }) { args.where = { ...args.where, organizationId }; return query(args); }, findFirst({ args, query }: { args: any; query: Function }) { args.where = { ...args.where, organizationId }; return query(args); }, create({ args, query }: { args: any; query: Function }) { args.data = { ...args.data, organizationId }; return query(args); }, createMany({ args, query }: { args: any; query: Function }) { if (Array.isArray(args.data)) { args.data = args.data.map((d: any) => ({ ...d, organizationId })); } else { args.data = { ...args.data, organizationId }; } return query(args); }, update({ args, query }: { args: any; query: Function }) { args.where = { ...args.where, organizationId }; return query(args); }, delete({ args, query }: { args: any; query: Function }) { args.where = { ...args.where, organizationId }; return query(args); }, } } })); } export function getTenantPrisma(organizationId: string) { return prisma.$extends(...createTenantExtension(organizationId)); }
Key Improvement: Generic Model List Instead of writing the same interceptor 200+ lines per model, define a list of tenant models and generate interceptors generically. Adding a new model = 1 line in the array.

Tenant Context Pattern

// Instead of passing organizationId everywhere... // Use a request-scoped context // src/server/context.ts import { cache } from "react"; import { auth } from "@/server/auth"; import { prisma } from "@/server/prisma"; export interface TenantContext { user: User; member: OrganizationMember; organization: Organization; prisma: ReturnType<typeof getTenantPrisma>; } export const getTenantContext = cache(async ( orgSlug: string ): Promise<TenantContext> => { const session = await auth(); if (!session?.user) throw new AuthenticationError(); const organization = await prisma.organization.findUnique({ where: { slug: orgSlug } }); if (!organization) throw new NotFoundAppError("Organization"); const member = await prisma.organizationMember.findFirst({ where: { organizationId: organization.id, OR: [ { userId: session.user.id }, { email: session.user.email } ] } }); if (!member) throw new AuthorizationError(); return { user: session.user, member, organization, prisma: getTenantPrisma(organization.id), }; }); // Usage in Server Actions: export async function recordDonationAction( orgSlug: string, input: z.infer<typeof donationSchema> ): Promise<ActionResult<Donation>> { const ctx = await getTenantContext(orgSlug); return DonationService.create(ctx, input); }

7. Auth & RBAC — Single Source of Truth

Current Problem — Three Authorization Systems

// System 1: Role-based (some services) const { member } = await validateAccess(organizationId, ["ADMIN", "TREASURER"]); // System 2: Permission-based (other services) await requirePermission(organizationId, "finance:create"); // System 3: Manual admin check (some actions) const member = await prisma.organizationMember.findFirst({ where: { organizationId, userId, role: "ADMIN" } }); if (!member) throw new Error("Only admins");

Proposed — Single Permission System

// src/server/auth.ts export const PERMISSIONS = { ADMIN: [ "finance:read", "finance:create", "finance:approve", "members:read", "members:invite", "members:manage", "events:read", "events:manage", "tasks:read", "tasks:manage", "bhog:read", "bhog:manage", "org:manage", "audit:read", ], TREASURER: [ "finance:read", "finance:create", "finance:approve", "members:read", "events:read", "tasks:read", "tasks:updateOwn", "bhog:read", "audit:read", ], COMMITTEE_MEMBER: [ "finance:read", "finance:create", "members:read", "events:read", "events:manage", "tasks:read", "tasks:manage", "bhog:read", ], VOLUNTEER: [ "tasks:read", "tasks:updateOwn", "events:read", ], } as const; export type Permission = typeof PERMISSIONS[keyof typeof PERMISSIONS][number]; // SINGLE function for ALL authorization export async function requirePermission( organizationId: string, permission: Permission ): Promise<TenantContext> { const ctx = await getTenantContextById(organizationId); const allowed = PERMISSIONS[ctx.member.role]; if (!allowed.includes(permission)) { throw new AuthorizationError( `Required permission: ${permission}` ); } return ctx; } // No more validateAccess(), no more manual admin checks // Every service uses the same function

9. Server Actions — Uniform Contract

Current Problem — Mixed Return Types

// Pattern 1: actionSuccess/actionFailure (donations, expenses) return actionSuccess(donation); return actionFailure("Failed to record donation"); // Pattern 2: Raw objects (members, events, bhog) return { success: true as const }; return { error: "Failed to create event" }; // Pattern 3: Custom shape (auth) return { success: true, userId: user.id }; return { error: "Email already exists" };

// src/server/actions/types.ts export type ActionResult<T> = | { success: true; data: T } | { success: false; error: string; code?: string }; export function actionSuccess<T>(data: T): ActionResult<T> { return { success: true, data }; } export function actionFailure( error: string, code?: string ): ActionResult<never> { return { success: false, error, code }; }

Action Wrapper Pattern

// src/server/actions/wrapper.ts // Eliminates repetitive try/catch + revalidation import { revalidatePath } from "next/cache"; import { ActionResult, actionSuccess, actionFailure } from "./types"; import { normalizeError } from "@/server/errors"; export function withAction<T, A extends any[]>( fn: (...args: A) => Promise<T>, options?: { revalidate?: string | string[] } ) { return async (...args: A): Promise<ActionResult<T>> => { try { const result = await fn(...args); if (options?.revalidate) { const paths = Array.isArray(options.revalidate) ? options.revalidate : [options.revalidate]; paths.forEach(revalidatePath); } return actionSuccess(result); } catch (e) { return actionFailure(normalizeError(e)); } }; } // Usage: export const recordDonationAction = withAction( async (orgSlug: string, input: CreateDonation) => { const ctx = await requirePermission(orgSlug, "finance:create"); return DonationService.create(ctx, input); }, { revalidate: (orgSlug: string) => `/${orgSlug}/dashboard/donations` } );

What Makes This Design Efficient

1. Single Authorization Function No duplicate patterns, no manual checks, one source of truth. Audit every permission check by grepping for requirePermission.
2. TenantContext Carries Everything No passing organizationId as a separate parameter. Context has user, member, org, and scoped prisma client.
3. Uniform Action Contract Every action returns ActionResult<T>. Client components have one error-handling pattern.
4. Generic Tenant Scope Adding a new model to tenant isolation = 1 line in an array. No 200-line boilerplate per model.
5. Co-located Tests Tests live next to the code they test. Easy to find, easy to maintain.
6. Loading & Error Boundaries by Default Every route segment has loading.tsx and error.tsx. No blocked renders.
7. Type-Safe Throughout No as any. Compile-time guarantees catch errors before runtime.
8. Module Boundaries Each module owns its models, services, types, and tests. No cross-module logic leaks.
